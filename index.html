ERP 智能运维与实施支持 Agent

面向 ERP 日常运维与实施支持场景构建的智能 Agent 原型， 将知识检索、ERP API / SQL 查询、业务规则判断、异常诊断与 UAT 辅助 整合至统一工作流。

Python ERP API SQL RAG Dify UAT

01｜业务问题与项目目标

ERP 运维支持中，常见问题往往需要在业务规则、系统数据和操作知识之间反复核对。 本项目围绕订单、库存等典型 ERP 场景，设计统一的智能支持入口： 用户使用自然语言提问后，由 Agent 判断问题类型，并选择知识检索、 ERP 数据查询或异常诊断路径。

02｜系统架构

用户自然语言问题
↓
Dify Agent / Workflow
↓
意图识别与任务路由
↓
RAG 知识检索　｜　ERP HTTP API　｜　SQL 数据查询
↓
业务规则判断 / 异常诊断
↓
结果整合 + 诊断依据 + 处理建议

设计重点：不是让大模型直接猜测 ERP 状态，而是将回答建立在知识内容、 业务数据和明确规则之上。

03｜核心能力

RAG 知识检索

针对流程、字段及异常处理类问题检索 ERP 运维知识，为回答提供上下文依据。

ERP API / SQL 查询

查询订单、库存等业务数据，将自然语言问题映射至结构化 ERP 数据。

业务规则诊断

结合订单状态、库存数量及业务规则识别阻塞条件，而非仅返回原始数据。

UAT 辅助

围绕正常、异常与边界条件设计测试 Case，验证接口与业务规则的一致性。

04｜代表性 Case：库存不足诊断

用户问题
为什么销售订单 SO100 无法继续处理？
Agent 处理链路
识别为订单异常问题 → 查询订单信息 → 获取对应 SKU 需求数量 → 查询当前可用库存 → 执行业务规则判断。
诊断结果
当可用库存不足以满足订单需求时， 返回 BLOCK 状态，并指出库存不足为当前阻塞原因。

该 Case 用于验证 Agent 是否能够完成 “问题理解 → 数据查询 → 规则判断 → 可解释结果” 的完整链路。

05｜其他典型场景

ERP 知识问答

流程、字段及操作规则类问题优先进入 RAG 检索路径，并基于知识内容生成回答。

订单状态查询

通过 ERP 接口或 SQL 获取订单状态及关联数据，避免模型直接生成业务事实。

异常定位

将查询结果与预设业务规则组合，输出异常原因及后续排查方向。

06｜测试与验证

API

验证接口可访问性、请求参数及结构化响应。

SQL

验证订单、库存等业务数据查询结果。

UAT

覆盖正常、异常及边界业务场景。

Regression

对核心业务规则进行回归验证，避免修改导致既有逻辑失效。

测试重点并非单纯验证接口“能运行”，而是检查 业务规则、异常路径、返回依据及结果可解释性。

07｜项目实现与边界

项目完成了 ERP 支持场景下的后端接口、数据查询、知识检索、 业务规则诊断、测试 Case 与容器化配置，并形成 Dify Agent / Workflow 集成方案。

当前版本定位为可运行的 ERP 智能运维与实施支持原型， 重点验证 Agent 与企业业务系统结合时的系统设计与业务闭环， 并非真实企业生产 ERP 环境。
